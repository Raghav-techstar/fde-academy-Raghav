# ADR-001: Use FastAPI BackgroundTasks for Analytics Refresh

## Status

Accepted

## Context

The Day 16 FastAPI service includes an analytics refresh operation that takes several seconds to complete. Running it directly inside the API request would make the client wait for the operation to finish. I needed a simple way to run the refresh in the background while returning a response quickly.

## Decision

I decided to use FastAPI BackgroundTasks for the analytics refresh operation.

## Alternatives Considered

- Run the refresh synchronously inside the endpoint — rejected because the client would have to wait for the operation to finish.

- Use a task queue such as Celery with Redis — rejected for this project because it would add extra infrastructure and configuration for a relatively small background task.

## Consequences

+ The API can return a response quickly while the refresh continues in the background.

+ The implementation is simple and does not require additional task-queue infrastructure.

- If the FastAPI server crashes or restarts during the refresh, the background task can be lost.

- For longer or business-critical jobs, a persistent task queue would be more reliable.
